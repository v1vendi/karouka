Neon frame: border-image

An inline SkSL string as border-image-source, sliced with fill so the shader also paints the card's glass interior. Two comets run around the frame in opposite directions at a constant speed along the edge, light the glass as they pass, and bloom into border-image-outset. Slice and width are equal, so each of the nine pieces maps 1:1 back onto the shader. Hover swaps the --c1/--c2 colors.

Liquid glass


One shader draws both the backdrop and the glass. A shader can't read the page behind it, so the backdrop is a
function in liquid-glass.sksl: drifting color blobs, stripes, a dot grid and rings. The glass evaluates
that same function at bent coordinates, pulled along its edge normal most near the rim, split by color and
frosted, so the stripes and rings visibly bend at its edges. Its shapes are joined with smooth-min, so the droplets
melt into the toolbar as they drift. The text on the glass is HTML laid out over the matching shapes.

Shaders inside layout


Each bar is a flex item whose height is keyframed, so the layout changes every frame. With
background-attachment: fixed every bar opens a window onto one continuous field instead of
restarting the shader per box. The drop cap is a ::first-letter float filled through
background-clip: text, and the inline status dots sit in the text and wrap with it.

Shaders embedded in HTML


The fire's SkSL sits in a <script type="text/x-sksl"> block. Six lines of script turn it into a
shader("…") string, escaping newlines as \A so its // comments survive. The
cursor is a shader written straight into a style attribute: the viewer draws no
cursor: url() images, so the cursor is an element moved by transform. Moving an element adds
no new shader argument, so the registry doesn't grow. Move the pointer over the fire.

Canvas input: a CRT


--tex element(#paint) binds an off-screen 2D canvas as the shader's uniform shader tex.
Script draws into the canvas each frame at 2x, and crt.sksl scales it to cover the screen (--res is the canvas's size), warps it, splits RGB and adds scanlines. The
caption is ordinary text over the result.

Glass progress ring


A progress bar as seven nested acrylic bands on a wooden table, ported from aladiN's "glass rainbow stacker"
(shadertoy.com/view/sXdSz7): its closed-form glass, room and palettes, without its state buffers. Every ray crosses
the bands with Fresnel, refraction, total reflection, Beer-Lambert tint and dispersion; the progress front glows with
the light the glass pipes, and the window behind throws coloured shadows. CSS drives it: the uniforms are
@property-registered custom properties, so Play and Orbit are @keyframes started by a
checkbox through :has(), and the percentage is a counter() of the same property. Whole
steps keep each run to the same images. The only script copies a slider's value into its property.




  

    
  

  

    
    
    
    
    
    

      
      
    

  

  











Fire on the DOM


XT95's raymarched flame (shadertoy.com/view/MdX3zr, CC BY-NC-SA 3.0) in flame.sksl, with a
transparent night so it composites over the page. One file serves every fire here: --tongues splits the
box into flames with their own noise and height, --seed varies them, --cool turns them into
a blue gas flame. The flames are pseudo-elements behind a heading and three cards. Hover
a card to set it alight.
